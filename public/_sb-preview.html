Terra Editor design system

Everything the 3D editor is built from — the tokens, the two typographic worlds, the visionOS glass material, and the panel/field/pill primitives. Every block below is live, and the code under it is what you paste.

Colour

Semantic roles, not literal colours. Every value resolves through a token so light and dark both work — nothing in the editor hardcodes a hex.

Surfaces & content

Roles

On-glass roles

The raw role tokens are tuned for solid dark chrome. On a tinted glass ornament over a bright scene they land at nearly their own lightness and the label disappears into its background — these lift the same hue clear of it.

Scene palette

Colours split by whether they theme, not by who consumes them. Chrome and glass are CSS custom properties. Axis, outline, gizmo and object colours are mode-stable and live in scene-palette.ts — Three.js needs numbers, canvas and SVG need strings, and none of them can read a CSS variable.

Type — chrome

UI type in glass panels and on solid surfaces. A style sets the face only — family, size, weight, tracking, case. Colour stays a separate utility, so one style works across every tone. -strong always means one weight step up from its base.

<h2 className="type-panel-title text-content">Desert Dunes</h2>
<p  className="type-body text-content-muted">Image asset placed in the scene.</p>
<h3 className="type-eyebrow text-content-subtle">Details</h3>
Escape hatch. A Tailwind type utility beside a type-* class wins — utilities layer over components. Use it for genuine one-offs, but never leave a stale text-xs next to a type-body: it silently defeats the style.

Type — scene

Diegetic type for the object label, which sits in the scene on a 3D-tilted plane. Light Inter at weight 300, tall-condensed by a synthetic scaleY/scaleX pair because neither Inter nor Sora ships a width axis. Two tiers, two ratios — the title is squeezed harder (1.28/0.8) than the meta row (1.18/0.86) so the block reads as a hierarchy.

Glass tiers

The visionOS overlay material. Glass ornaments are DOM layers floating above the WebGL canvas — never Three.js objects. Thickness is body; blur is separation.

Thickinspectors
Chromepills
Overlaymenus
<GlassPanel ui="object-info" thickness="thick">…</GlassPanel>

// thin · regular · thick · chrome · overlay
Overlay is the one that isn’t just a thicker step. Every tier below it assumes glass floats over the scene; a menu doesn’t — it covers other chrome. Blur alone can’t fix that (it smears a shape without removing it), so overlay shares thick’s body — a popover and a panel side by side must read as one surface — and spends its whole budget on blur: 24px against the panel’s 8px.

Scene lighting variants

Glass is translucent over a scene nobody controls, so one tuning can’t work everywhere. The editor samples the rendered frame and stamps data-scene on its root; the overrides inherit to every ornament below.

TierBodyEdgeWhy
dark0.22hairline /0.30The ink has nothing to darken — let the edge define the shape
dim0.30/0.18The tuned baseline
bright0.40/0.14The light label is at risk; the edge already reads
Thresholds are calibrated against measured frames, not intuition: the default desert HDRI sits at ~0.39 mean luminance, and a frame only passes ~0.6 if a blown-out sky fills it. Each bound has a dead band so a slow orbit doesn’t oscillate the chrome.

Active role tint

For a toolbar tile that is on. The tint layers over the glass ink as a background-image rather than replacing it — a role colour set as background-color wipes out the dark base, and the label (the same role colour) ends up on a wash of itself.

  "type-label glass glass-interactive",
  active   && "glass-role glass-role-brand  text-brand-on-glass",

Field

Button

The solid-surface button, used in panel footers and the top bar. Size owns both the box and its text style — the button scale is tied to control height, not to the prose ramp.

Layer naming

Every component names its internal parts via data-ui, derived from the instance name through context. The same identifier is traceable across Figma layer, code, and runtime.

Rules

RuleWhy
No raw text-* / font-*Every face is a named type-* style. A raw utility beside one means the style is wrong — fix the style or add a role.
Modifiers compose, faces don’ttabular-nums, truncate, leading-*, uppercase and colour utilities are fine next to a style.
Colour is a separate utilityA style sets the face only, so one style works across every tone.
Never bg-<role>/x on glassIt sets background-color and replaces the glass ink. Use glass-role, which layers the tint over it.
Icon-only controls need labelRequired by the prop types on IconButton, GlassIconButton, GlassGhostButton.
Popovers use thickness="overlay"Anything covering other chrome rather than the scene.
Name a role when it recursSingle-use deviations should be rare enough to argue about.
